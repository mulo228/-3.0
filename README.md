# БЕЗ ОЧЕРЕДИ — MVP-прототип сервиса предзаказа еды

**БЕЗ ОЧЕРЕДИ** — интерактивный учебный MVP сервиса предзаказа готовой еды для студентов и сотрудников Финансового университета. Проект подготовлен по концепции команды **«5 и точка»** для Академии Финтеха ВТБ (2026).

Идея проста: **выбрал готовый обед → оформил предзаказ → пришёл в столовую → забрал заказ по QR-коду или номеру**. Сервис задуман как раздел «Питание» на сайте университета, без установки отдельного приложения, без доставки и без приготовления блюд специально под заказ.

> **Статус проекта:** работающий интерактивный *фронтенд-прототип*. Сайт демонстрирует действия покупателя и сотрудника столовой, но не подключён к настоящей системе университета, серверу или платёжному сервису.

## Для чего нужен проект

Во время коротких перемен многие студенты одновременно приходят в столовую. Время уходит не только на получение еды, но и на выбор блюд, ожидание в очереди и оплату.

«БЕЗ ОЧЕРЕДИ» предлагает перенести выбор и оформление заказа в браузер. Столовая заранее видит состав заказа, собирает готовую еду из доступных остатков и выдаёт её покупателю. Насколько это сокращает ожидание, нужно проверить в реальном пилотном запуске — MVP не измеряет экономию времени.

## Возможности демоверсии

### Для студента / покупателя

- **Главная страница:** яркий адаптивный дизайн, иллюстрация блюда и описание работы сервиса.
- **Меню на сегодня:** восемь демонстрационных блюд с названиями, категориями, описаниями, ценами и текущими условными остатками.
- **Поиск и фильтрация:** поиск по меню и категории «Горячее», «Супы», «Салаты», «Завтраки», «Напитки».
- **Корзина:** добавление и удаление блюд, изменение количества, автоматический расчёт итоговой суммы. Нельзя добавить больше единиц, чем есть в остатках.
- **Оформление предзаказа:** заказ только на текущий день; имя для выдачи можно указать по желанию.
- **Выбор оплаты:** «При получении» либо «Онлайн — симуляция оплаты». **Деньги не списываются.**
- **Номер и QR-код:** после оформления появляется номер заказа и **считываемый QR-код**, содержащий строку вида `BQ-1044` (номер зависит от конкретного заказа). Можно скопировать номер.
- **«Мои заказы»:** просмотр последних 12 заказов, сохранённых в демонстрационных данных этого браузера, их сумм и статусов.

### Для сотрудника столовой

- **Панель столовой:** доступна по кнопке «Панель столовой» в шапке сайта или через мобильное меню.
- **Список заказов:** номер, имя покупателя, состав, сумма, время, отметка об оплате и текущий статус.
- **Фильтры:** активные, все, выданные; поиск по номеру заказа или имени.
- **Обработка заказа:** последовательные статусы **«Принят» → «Собирают» → «Готов к выдаче» → «Выдан»**.
- **Оплата при получении:** сотрудник может отметить её как подтверждённую; реальной кассовой операции при этом нет.
- **Учёт остатков:** ручное изменение количества доступных блюд кнопками `+` и `−`.
- **Показатели:** количество активных и готовых заказов, число выданных заказов и сумма заказов (включая демонстрационные примеры).
- **Сброс демо:** восстановление исходных заказов и остатков.

### Общие особенности

- Адаптивный интерфейс для компьютера, планшета и телефона.
- HTML, CSS и JavaScript находятся в одном `index.html`; внешние библиотеки не требуются.
- Состояние заказов и остатков хранится в `localStorage` браузера и сохраняется после обновления страницы.
- Ключ хранилища содержит текущую **локальную календарную дату**, поэтому на следующий день создаётся новое демонстрационное состояние.
- При первом открытии сайта для каждого дня загружаются **два примера заказов**, чтобы сразу показать работу панели столовой.

## Как работает сайт: сценарий демонстрации

1. **Откройте меню.** Выберите, например, «Курица с рисом» и «Морс ягодный».
2. **Перейдите в корзину.** Проверьте состав и итоговую стоимость, при необходимости измените количество блюд.
3. **Выберите способ оплаты.** Для наглядного сценария можно выбрать «При получении» или симуляцию онлайн-оплаты.
4. **Нажмите «Оформить предзаказ».** Сайт сформирует номер заказа, QR-код, статус «Принят» и уменьшит условные остатки выбранных блюд.
5. **Откройте «Мои заказы».** Новый заказ появится в списке. Нажатие на него откроет карточку с QR-кодом.
6. **Перейдите в «Панель столовой».** Найдите заказ по номеру или имени.
7. **Обработайте заказ:** «Начать сборку» → «Готов к выдаче» → «Выдать заказ». Если выбрана оплата при получении, сотрудник может дополнительно нажать «Подтвердить оплату».
8. **Вернитесь к покупателю.** Повторно откройте заказ: его статус изменится на «Выдан».

**Важно:** студент и сотрудник работают с одними демонстрационными данными, только если они открывают сайт в **одном и том же браузере и хранилище сайта**. На двух независимых устройствах заказы не синхронизируются.

## Как запустить локально

**Самый простой способ:** скачайте или распакуйте архив и откройте файл `index.html` двойным нажатием в современном браузере (Chrome, Firefox, Edge, Safari). Для основной демонстрации подключение к интернету, установка зависимостей и сборка не требуются.

**Альтернативный способ — через локальный сервер:**

1. Откройте терминал в папке проекта.
2. Выполните команду:

   ```bash
   python -m http.server 8000
   ```

3. Перейдите по адресу **http://localhost:8000**.

В некоторых браузерах работа хранилища при открытии `file://` имеет особенности; локальный сервер даёт более предсказуемый результат.

## Публикация на GitHub

1. Создайте пустой репозиторий на **https://github.com/new**, например `bez-ocheredi-mvp` (без автоматически добавляемого README, если используете команды ниже).
2. Распакуйте архив и откройте терминал в папке с `index.html` и `README.md`.
3. Выполните команды:

   ```bash
   git init
   git add .
   git commit -m "Добавлен MVP сервиса Без очереди"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/bez-ocheredi-mvp.git
   git push -u origin main
   ```

4. Вместо `ВАШ_ЛОГИН` укажите свой логин GitHub. Репозиторий будет доступен по адресу `https://github.com/ВАШ_ЛОГИН/bez-ocheredi-mvp`.

### Как получить ссылку на работающий сайт (GitHub Pages)

1. В репозитории откройте **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Deploy from a branch**.
3. Выберите ветку **main**, папку **/(root)** и нажмите **Save**.
4. После публикации адрес обычно будет иметь вид `https://ВАШ_ЛОГИН.github.io/bez-ocheredi-mvp/`.

Публикация на GitHub Pages подходит для демонстрации, поскольку проект статический. Данные по-прежнему будут храниться локально у каждого посетителя; общих заказов между пользователями не появится.

## Ограничения MVP

Это **учебная демонстрация интерфейса**, а не система для работы столовой с реальными продажами.

- **Нет сервера и общей базы данных.** Все заказы, статусы и остатки хранятся только в `localStorage` конкретного браузера, без синхронизации между устройствами.
- **Нет авторизации и разделения ролей.** Любой пользователь демоверсии может открыть панель столовой.
- **Нет реальной оплаты.** Режим «Онлайн» лишь помечает заказ как оплаченный в демо; режим «При получении» позволяет вручную подтвердить оплату. Банковские данные не запрашиваются.
- **QR-код настоящий, но без серверной проверки.** Он кодирует короткий идентификатор заказа и может считываться обычным сканером, однако сканирование само по себе не меняет статус и не подтверждает выдачу.
- **Остатки условные.** Резервирование выполняется только в локальных демо-данных. Нет защиты от одновременных заказов с разных устройств.
- **Нет полноценного офлайн-процесса для столовой.** Локальное открытие страницы возможно, но офлайн-сверка и последующая серверная синхронизация не реализованы.
- **Нет интеграций:** отсутствуют университетская авторизация, платёжный шлюз, кассовое ПО, фискализация, email/SMS-уведомления и автоматическая проверка QR на выдаче.
- **Нет производственных правил:** не реализованы отмены, возвраты, подтверждение фактической доступности товара и безопасное хранение персональных данных.
- **Демонстрационные данные можно сбросить** кнопкой в панели столовой или очисткой данных сайта в браузере. Новый календарный день создаёт отдельный набор данных.

Перед реальным запуском понадобятся сервер и API, база данных, разграничение ролей, безопасная авторизация, согласованное с кассой проведение платежей, атомарное резервирование остатков, обработка отмен/возвратов, защищённая выдача заказов и тестирование безопасности.

## Технологии

- **HTML5** — структура страниц.
- **CSS3** — адаптивный дизайн, анимации и оформление.
- **Vanilla JavaScript** — корзина, заказы, статусы, панель столовой, генерация QR-кода.
- **localStorage** — хранение демонстрационного состояния браузера.
- **SVG** — встроенная в страницу иллюстрация и QR-коды.

Никаких сторонних фреймворков, сборщиков и сетевых API для запуска не требуется.
